# Ponkun News: v0.1以降の設計メモ

v0.1は手動更新のみ。ニュース用SQLiteはチャット履歴・共有長期記憶とは分離する。

1. 毎朝7:30の収集：独立したスケジューラから既存の`refresh()`を呼ぶ。タイムゾーン、端末スリープ、同日重複実行、費用上限を確認するまで有効化しない。現在の上限はニュース設定画面から変更できる（初期値20回/日、300回/月、推定$20/月）。日次・月次の区切りは日本時間。スケジュールを有効にする前に費用上限と実際の請求額を確認する。
2. 重要ニュースの臨時通知：記事の新規性と重要度を別途判定し、ユーザーが通知を明示的に許可した場合だけ送る。収集と通知の失敗を切り離す。
3. Android Web Push：HTTPS、Service Worker、購読情報の暗号化保存、購読解除、VAPID鍵管理、通知権限を設計してから実装する。v0.1のService Workerは変更しない。
4. おすすめ度改善：`interested` / `not_interested` / `read`をニュース専用DBから集計し、ジャンル単位の重みを調整する。会話履歴や共有記憶は学習入力にしない。

いずれもv0.1では未実装・無効。
